# 从两次制作中得到的经验

这些经验来自 Sakee 与 ASEN 两次试作及其制作 trace。它们用于改进方法，不将某位创作者的喜好设成所有视频的默认要求。原始 trace 与私人素材不随插件发布。

## 有哪些实证

ASEN V1有20镜头、9个环境，但用户仍认为细节精致、整体场面单一。镜头数、背景数和图集姿势数不能代替对事件、人物关系、空间变化与内容意图的检查。

Sakee的上车、突破和扣篮包含准备、接触、结果与回应，这种事件完整性值得复用。ASEN后来试作了参考作品的翻栏和扣篮，用户要求撤回，改为依据当前歌词演出。可复用的是方法，具体动作仍要服务本片。

ASEN的开场从文字表现改成实物挥锤，以及后来调整横竖画幅，都说明高成本选择应在资产批量生成前通过代表性画面和动态小样验证。画幅变化在本次是较晚提出的要求，不应描述为 agent 违反已有明确约束。

## 效率优先级

按完成的工具事件统计，ASEN三个版本共50次图片生成；生成服务记录的耗时相加约47.2分钟，考虑重叠后的区间并集约38.1分钟。三次完整MP4导出合计约4.7分钟，各对应一个交付版本。会话墙钟时间还包含人工讨论、等待和其他工作，不能直接当计算耗时。

因此，先验证关键内容、构图和真实交互，再扩展下一批资产，通常比只优化最终导出更值得优先做。局部小样用于提前发现问题；最终交付仍需要整片导出与检查。

原始 trace 的绝大多数序列化体积来自图片/base64，并含事件与结果中的重复记录。日志文件体积不能直接换算成模型成本、独立 token 数或文本浪费。视觉检查本身仍有必要，宜先总览、后定向细看。

## 本插件落实的方法

- 在计划中写清关键事件、对应内容与早期小样的验证目标。
- 提供 `render --scene` / `--start --duration`，无需为局部小样重写渲染脚本。
- 提供 `frames`，按具体动作时刻取样、生成带时间标注的总览，区分源工程与编码成片证据。
- 通过 reviewing-video 分开记录技术有效、动作/内容判断和用户反馈。
- 先检查关键资产的透明区域、图集边界和接触挂点，再扩展同类生成。
- 保留同一用户工程、素材、音轨和字幕时间轴；局部修改先定向复查，再交付完整版本。

## 不自动推广的结论

安静背景、讲解和氛围视频可以有意减少运动；动作多、切镜快并不总是更好。技术通过、帧哈希不同或检查图很多，都不能据此宣布用户满意。不同画幅和不同内容也不能直接套用同一套动作。
