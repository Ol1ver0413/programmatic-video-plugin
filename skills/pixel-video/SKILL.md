# Pixel Video

帮助创作者把音频做成有情节、有动作的像素视频。使用宿主的图片工具制作角色与场景，用 Canvas 编排动画，用 FFmpeg 导出。生成资产可以替换，时间轴和动作可以继续编辑。

## 开始与恢复

先找用户的音频、参考图、现有视频工程和约束。沿用已选音频和已确认的风格；用户只改动作或细节时，不要重新选段、转写或重做全部素材。已有可运行工程时直接修改它。

新项目使用本 skill 的 `scripts/pixel-video.mjs`。下文的 `<skill-dir>` 是当前 `SKILL.md` 所在目录，`<project>` 是用户可写的作品目录，包含空格的路径要引用。把依赖、素材和导出都写到作品目录，不要写插件安装目录。

```sh
node "<skill-dir>/scripts/pixel-video.mjs" doctor
node "<skill-dir>/scripts/pixel-video.mjs" init --out "<project>" --audio "/path/voice.wav"
```

`init` 复制可编辑的 Canvas 工程和本地音频。选段时先用 `audio` 命令裁出文件，再初始化；命令参数见 [工具与工程约定](references/toolkit.md)。没有真实素材时可以用 `init --out "<project>" --demo` 跑八秒原创动作样例。

## 音频与字幕

先确定实际音频的时长、选段和必须包含的内容。优先使用用户给出的 SRT 或时间戳 JSON；没有字幕时，使用当前宿主可用的转写与对齐能力，记录来源和校验状态。工具包本身不提供 ASR，不要把估算时间或公开歌词时间轴称为逐字准确对齐。

本工程所有时间都是**裁切后视频内的秒数**。原曲时间必须减去裁切起点。保留每句起止时间，导出独立 SRT，并在画面中烧录。检查片头、指定句、镜头切换处与片尾，尤其检查一句只截进来一小部分的边界。

## 从语义到镜头

先为选段写一个紧凑的分镜：每镜的时间、歌词/口播意图、环境、角色动作、道具交互和镜头变化。篇幅由内容决定，不固定为 24 镜头或某种时长。需要整体改进时先看关键帧或原片，找出重复和平淡的段落。

核心是可见的动作过程：准备、发力/接触、结果、收势。跑向车、开门、坐入、关门、加速；运球、蓄力、起跳、触框、落地。关键道具跟着手、身体或载具运动。让同一人物只横向滑过不同背景，不能算动作丰富。

按需阅读 [分镜与动作](references/direction.md)。随后在工程的 `src/scenes.js` 中编排，`project.json` 中登记镜头。少量长镜头可以有连续变化；一句歌词也可以有多个镜头，不必逐字照搬。

## 素材与角色一致性

使用宿主已提供的图片生成/编辑工具；工具不可用时说明情况，使用已有素材或原生 Canvas 绘制，别声称生成了没有生成的图片。保持参考人物的辨识特征、色板和比例。只有用户要求补充外部参考时才据此检索，并确认照片确实属于目标人物。

可分开制作背景、角色动作图集、道具与近景。保存生成图的原文件、提示词和参考来源到作品目录，保留已生成的版本。透明图集必须检查 alpha 通道；白色或棋盘背景可能是图的一部分。检查每个网格内是否混入相邻姿势。

必须准确的数字、字母和标识用代码绘制。随姿势分别设置挂点，检查是否盖住原牌子、是否漂浮或左右镜像。资产字段和挂点示例见 [工具与工程约定](references/toolkit.md)。

## 预览、迭代和交付

在作品目录安装依赖、预览和导出：

```sh
npm install
npm run check
npm run stills
npm run dev
npm run render
```

先看分镜静帧和关键动作的连续帧，再导出整段。用浏览器核对实际播放、暂停、拖动和字幕；代码报错要先解决。模板导出会检查容器时长、画面尺寸、帧数和音轨，并完整解码 MP4；这些检查不代替视觉和听觉复核。

动画只由时间和已保存的素材决定；随机效果用固定种子，不用当前系统时间或无种子随机数驱动导出。音频和画面用同一秒数时间轴。修改已选片段时保持音频路径和字幕时间轴，除非用户要求改变。

交付 MP4、SRT、分镜预览、素材目录和可编辑工程，说明实际验证了什么。渲染失败时不要把静帧称为成片。视频发布、外部上传、仓库推送按用户当前授权执行。
