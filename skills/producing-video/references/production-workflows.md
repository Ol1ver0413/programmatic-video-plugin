# 四种制作配方

按实际任务选择，复用现有CLI，不引入工作流引擎。工具参数与缓存约定见[制作工具](../../using-programmatic-video/references/production-tools.md)。

## 新项目

从brainstorming接收当前目标，writing-plans先写内容脚本、再排分镜。音乐/配音片先落实可用选段与主要语义时刻；未定部分标清，先做不依赖其时间的素材和结构稿。无声作品使用自身叙事或信息时序。

brief保存当前要求，plan解释故事与镜头，project.json管理执行时间、资源与参数。历史只留引用，恢复用context --summary，再按需读当前文档。镜头内事件使用scene.events/local/progress，跨镜持续事件使用同一确定性表演轨，避免每次切镜重启动作。

先把素材需求与已有资产对应，列出直接复用、局改和必须新增的部分。同类新资产按实际显示尺寸与细节要求选择素材表或单张，采用[素材复用策略](asset-reuse.md)，在现有记录里维护用途和版本。

## 小样与长片扩展

选择能代表关键表现难点和相邻事件交接的短段验证。方向存在实质分歧时用少量可对照方案，避免先做多套全片资产。图集用atlas准备/打包/登记，候选仍需看过再采用。

新方法先比较同一短段的动态效果；分开记录画风、单个资产、动态小样和全片的认可范围。用 preview --input ... --compare ... --write-only 呈现版本，不逐版编写网页。当前比较按钮按各自片段0秒播放，片内起点不同的片段须先按导出映射定位同一范围。

资产扩展沿用已认可参考，批量大小随清晰度和可用率调整；少数条目失败只补失败部分。对素材表逐项查看，并放入实际镜头检查，不凭生成成功或格数判断可用。

长片扩展前，用现有资产或占位画面做一次draft全长预演，检查信息推进、重复表达、转折与尾段；按反馈改脚本和场面。正式精修只扩展已明确的需求。小样证明局部可行，全长粗稿检查结构，两者各有用途。

## 局部修改

先用project --input/--time找到实际被反馈的导出版本，再维护当前工程。明确是内容、素材、动作、镜头、字幕还是导出问题。用patch --dry-run查看变化范围，完成后局部render --profile draft；共享原版证据，补关键动作与邻接剪辑。

可以通过场景代码或已有素材局改满足要求时，保持其他资产；确需新姿态、交互或细节时定向补做。合格源图保持原文件，新版本仅替换相关引用并复查实际镜头。

源码符合隔离约定时可用incremental重建完整版本；未知共享依赖则保守重做。改时长不默认等价于加速整个动作：保留必要的准备、接触、受力和恢复，压缩后重新看。前一版本通过的局部检查，只说明前一版本和已记录范围。

## 最终交付

确定时间、资产和字幕后，按final规格输出。先看全局：每段是否推进本片意图，重复事件是否有目的，角色是否可辨，景别/参与方式是否符合方向，有没有无意的信息空窗。安静、留白或静态本身可以是设计。

再结合既有技术证据检查最终编码、字幕和音轨。独立reviewer集中反馈，只重查变化点及其影响，保留未验证项。交付与沉淀仍走finishing-video/finish；draft或一段小样不代替完整正式交付，也不把缓存命中当艺术验收。
