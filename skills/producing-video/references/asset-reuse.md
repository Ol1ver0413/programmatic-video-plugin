# 素材复用与批量生成

在准备新素材、扩展已认可风格或修复素材时读取。目标是以满足本片内容和画面质量的最少重复工作，获得可用资产。不限画风、人物或视频类型；素材表可以包含动作、表情、视角、道具、插画元素或相关背景。

## 从已有资产开始

在本工程、用户提供的资产及已知可用的前作中，核对身份、风格、来源、实际清晰度、透明背景和使用范围。把直接复用、局改和确需新增的资产及对应镜头写进现有 plan.md；来源与采用版本沿用 assets/sources.json 和 project.json，不新增平行台账。

镜头裁切、缩放、平移、图层编排和可控动画可直接使用已有图像。缺少身体动作、真实握持/接触、身份特征或关键信息时，补这些实际缺口；用同一站姿反复缩放不能替代本片需要的演出。用户要求更换主体或风格时遵从新要求，不强行沿用旧图。

局改沿用已认可图像和适用参考，使用宿主实际提供的编辑能力，并检查它是否误改了身份、轮廓或其他细节。有已认可的角色/风格参考就直接作为依据；只有缺少依据且后续大量资产依赖它时，才先验证一份代表资产。

## 选择每次生成的内容与数量

同一批适合共享主体身份、风格或视觉条件，且每个条目都有明确镜头用途。姿势组按动作事件列出需要的准备、发力/接触、结果、收势；多视角组明确每项机位。不同条目可以有不同用途，不必为了填满格子生成无用变体。

| 条件 | 选择依据 |
| --- | --- |
| 一组相关且可独立裁取的素材 | 考虑素材表，减少重复设定与调用等待 |
| 面部特写、小道具细节、复杂多人接触 | 保留充分的主体像素和构图空间，减少条目或单独生成 |
| 少量候选就能验证形式 | 先生成足够验证的部分，通过后扩展有需求的资产 |
| 已有资产能满足新的镜头 | 复用或编辑，不因换镜头就重新生成整套素材 |

不固定九宫格，也不把“单次生成越多越好”作为目标。按工具实际返回的尺寸评估每项可用区域，扣除留白后，确认主体细节足以用于本片最大显示范围。放大不会补回缺失的脸、手或道具细节。像素画依据其逻辑像素和最终观感判断，不强制采用照片的分辨率标准。

设计候选和制作素材分别标记。候选表适合挑动作、身份与构图，合格条目可直接采用；只有入选条目在目标景别下像素不足时，再以原候选和风格依据补少格或单张高清图。不要强制每个素材都生成两遍，也不让近似整景重绘的身份、服装和背景漂移代替真实动作。

格数增加后若主体变小、交互拥挤、身份漂移或动作读不清，就减少同批条目、拆批或单张生成。不要先低质量密集生成，再反复放大或整套重做。

## 素材表的生成约定

提示词结合实际内容组织，不照抄固定动作或格数：

```text
用途：[本片需要的镜头和动作/信息]；画风：[已认可风格]。
参考：[每份参考分别控制身份、服装、风格或构图]。
布局：[按本次清晰度需要确定的行列或区域]。
条目：[逐项写清姿态/表情/机位/道具关系和用途]。
保持身份、服装、色板与身体比例一致；姿态组采用可校准的共同参考尺度。
每项完整落在其区域内，留出动作、道具和裁切空间，不跨格、不相互遮挡。
背景与透明要求：[按使用方式明确]；仅保留本次确实需要的图中文字。
```

需要透明资产时明确请求实际透明输出，并检查 alpha；白底不等于透明。双人互动或握持道具可以放在同一区域，共同验证接触关系，不为独立分格拆散必要交互。背景、复杂完整场景和图文构图按自身要求安排，不强行变成角色精灵图。

收到图后检查实际条目数、内容、细节与边界。布局没有按提示生成时，以实际区域校准或补受影响部分，不能仅凭约定行列数盲切。

多次生成/补图的请求和实际输出用 assets 的 prepare/import/adopt 保存，沿用 assets/sources.json，不再写逐版 save/record 脚本。请求明确每份参考的作用；相同请求和已导入文件可重试，修改提示词或参考需新请求版本。CLI 的整图尺寸检查不代表单格有效像素足够，内容、手势和 alpha 仍要看；采用登记也不等于用户认可。具体格式见[制作工具](../../using-programmatic-video/references/production-tools.md)。

## 使用已有图集工具

确认真实布局后，用 atlas 分析与校准，避免每片另写切图脚本。以下 3×2 只是六项素材的示例：

```sh
programmatic-video atlas --project "<project>" --input assets/action-sheet.png --columns 3 --rows 2 --out output/qa/action-candidate.json
```

核对候选区域，需要时提供显式 layout；再按需用 --pack 去除透明留白、--register 登记资产。批量准备可用 atlas --batch ... --resume。命令与格式见[图集工具](../../using-programmatic-video/references/production-tools.md#图集批量准备)。

atlas 生成几何信息，不保证人物身份、透明背景或动作正确。每个姿势分别校准手、脚和道具挂点，保持共同参考高度。关键姿势仍需由时间函数、镜头和交互过程组织成动画；一张表里的多幅图不自动构成流畅动作。

## 修复与停止

只有少数条目有问题时，携带原图、相关参考和具体缺陷，编辑或补生成这些条目。合格条目继续引用原文件，修复另存版本，避免重新生成整张表导致已认可部分漂移。全组主体或风格都错时，先修生成依据或分组，再重做受影响范围。

在实际使用尺寸检查新素材，并放入相关镜头做动态小样，连同邻接剪辑检查清晰度、接触与衔接。通过后停止生成；下一轮应有新的用户要求或可定位的缺陷。不要仅因为“还能更好”持续抽卡，也不要为减少调用跳过必要的质量修复。

沿用 progress.md 简记实际生成/编辑批次、采用条目、复用与补做原因、可获得的等待耗时。工具不提供费用时不估报金额；一张多项素材表不等于按项数等比例省钱。比较总耗时、可用素材和返工情况，再决定后续批量大小。
