# 制作视频

按 [入口指南](../using-programmatic-video/SKILL.md) 接手工程，沿用本次需求、已认可的声音字幕和资产。接口与命令见 [工具约定](../using-programmatic-video/references/toolkit.md)。

每次制作/修复维护同一份 project.json。用 `project --time ...` 定位场景、代码与素材；已接入代码的常调参数可用 `project --scene ... --set ... --value ...` 微调，再局部导出。小样完成后进入 reviewing-video，按通用检查与本片专项要求获取单个 reviewer 的集中反馈。

## 先验证关键表达，再扩展制作

长片先用已有素材或占位画面做低成本全长预演，检查整体推进与尾段，再扩展昂贵资产。关键短段用于验证难点和相邻场景交接；先确认形式，不把某个精致短段直接视为整片节奏已验证。新建、小样、局改与交付的具体配方见[制作工作流](references/production-workflows.md)。

先实现计划里的代表性场景，产出短动态小样：

```sh
programmatic-video render --project "<project>" --scene "<scene-id>"
```

按 [reviewing-video](../reviewing-video/SKILL.md) 看实际动作是否表达了内容、交互是否成立、画幅与字幕是否合适。静帧可以检查构图，动态效果要实际播放；小样尚未运行时不称为已验证。小样与观察结论写进 `progress.md`，再扩展下一批资产。

## 素材与场景

从 `plan.md` 的事件推导资产需求：身份、姿态、接触对象、挂点与构图。双人接触、手部交接可使用一组共同构图的动作资产；细小动作需要看清时切特写。角色/道具跨镜复用时保持身份、比例与状态延续，前作素材先核对适用性和来源再采用。

使用多份图像参考时标明各自控制什么：身份或品牌、画风、构图、环境。可先验证一份代表资产作为后续风格依据，避免把风格参考中的人物身份或故事也复制过去。像素/图集实现按需读 [分镜与动作](../using-programmatic-video/references/direction.md)。

复用用户资产，按需搜索或调用宿主图像工具。保存原文件、参考、提示词、版本与是否采用；生成成功只是获得候选素材。检查关键资产的透明区域、身份、色板、裁切、比例、姿势所需的真实道具或伙伴，再扩大同类生成。发现问题时修最小受影响集合。

像素图集按每个姿势校准手掌、脚底等挂点，使用统一参考身高，避免姿势边界变化导致人物忽大忽小。道具与接触点共用缩放、翻转、旋转变换。动画与信息图的事件设计、接触检查见 [分镜与动作](../using-programmatic-video/references/direction.md)。其他画风按需求选择原生画布、字体和资产；pixelArt 选项及当前限制见工具约定。

在工程场景模块中编排动画，以 `project.json` 登记时间和资源。按片内时间确定画面，随机效果固定种子；每镜用局部时间表达动作。背景、镜头和字幕都围绕本片意图，不用持续震屏或平移代替缺失的事件。准确人名、数字和标志文字用代码绘制。

## 修改范围与效率

优先用[可复用制作工具](../using-programmatic-video/references/production-tools.md)完成patch、draft、atlas批处理和共享取帧。确定性隔离场景可显式使用增量渲染；不自动改旧工程。镜头、人物、道具与挂点共用变换，字幕独立；复用底层绘制能力，按本片内容设计不同事件表达。

固定操作统一调用 CLI。图集先用 atlas 分析，再按需要用 `--layout` 校准实际区域、共同参考高度与命名挂点，输出可被公共绘制器读取的描述。LRC 和音频/小样时间映射用 captions；编码小样取帧可用 `frames --input ... --map ...`。失败后以相同参数和 `--out ... --resume` 续做原证据，换版本则新建目录。完整用法按需读 [可复用媒体工具链](../using-programmatic-video/references/reusable-tools.md)，避免重写检查与时间换算脚本。

录音定位继续用 `audio --mode locate`，音轨证据用 verify；整份编码规格、已选音轨与 sidecar 回归用 `validate --input ...`。公共绘制实现随新工程保留在 tools/，由 drawing.js 导出；作品场景只编排本片演出，不再各写一套裁切和挂点变换。既有工程的工具不会自动覆盖。

- 先判断问题属于语义、演出、素材、时间/字幕还是导出。语义错误先修事件设计，避免反复精修最终不会采用的姿势。
- 局部修改先检查该镜头、关键接触前后和邻接剪辑，再输出局部动态小样；正式交付仍导出完整成片。
- 通用取帧、总览和导出优先用 CLI；作品专属动作放场景模块。已有工程的自定义工具不自动覆盖。
- 需要检查播放器、音轨、字幕或时间逻辑改动时，可用 `validate --playback` 检查播放、暂停、拖动、结束与确定性；不必每片重写浏览器检查脚本。它检查源播放器，不替代编码成片审查。
- 工作文档继续使用 brief/plan/progress/review；小样放 `output/previews/`，取帧、检查报告和临时复盘输入集中放 `output/qa/`。按用途建目录，不为每次尝试复制工程。
- 先看总览定位，再放大问题帧；采样数量随动作调整。只读取当前需要的代码与报告，命令输出摘要和路径，避免反复倾倒整份工程或图片数据。
- 进度记录当前版本、预览路径、已验证与未验证内容、下一步。估时基于实际记录；图片生成等待、人工讨论、渲染耗时分别说明。

音频和字幕共享片内时间轴。已有时间戳可用 captions 转换；转写或强制对齐依赖宿主工具，估算时间不称为逐字准确。`audio: null` 支持无声，`captions: null` 或内容为 `[]` 的字幕文件支持无字幕，`burnCaptions: false` 输出干净画面与独立 SRT。

正式交付前进入 [finishing-video](../finishing-video/SKILL.md)。小样导出不表示整片完成，暂停和等待反馈用 checkpoint。
